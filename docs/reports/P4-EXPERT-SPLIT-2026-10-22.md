## 0. 结论

**`--pcie-frac` 不是一个可以手调的杠杆：引擎自带的默认值（启动时实测链路后取 0.55）就在最优点，
往两边各挪 0.2 都掉约 8% 吞吐。所以「按负载自适应调 pcie_num」的控制器没有必要做。**

三条支撑：
1. 四臂扫描（0.35 / 0.65 / 0.75 vs 默认 0.55）没有一臂超过默认，两个方向同时变差；
2. 机制上两条腿已经是平衡的：减少 PCIe 份额把「等 GPU」从 24.5 降到 12.3 ms，但「池 + 规划」从
   34.1 涨到 37.5 ms，净收益为负；反过来也一样；
3. CPU 池这条腿在 **9 个 blob / 34 ms（≈0.3–1 GB/s）** 的量级上，是**延迟/同步受限，不是带宽受限**，
   所以「把字节挪到 GPU 上读」在原理上也拿不到多少。

## 1. 这个旋钮改的是什么

`src/core/expert_source.cpp:3406-3442`：每层窗口先对路由条目去重，未命中的专家里
**最后 `pcie_num/256` 那一份由 GPU 直接经 PCIe 读**，其余交给 13 worker 的 CPU 池。
`pcie_num` 由 `--pcie-frac` × 256 得到；不给该参数时引擎在启动时实测 host→device 带宽，
22.8 GB/s → `pcie_frac 0.55`（`src/program/generate.cpp:2086-2099`）。

**硬上限**：`fetches < P.staging_cap && fetches < 64`（`expert_source.cpp:3477`），而
`staging_cap = kStagingBlobs = 16`（`src/core/verify.cpp:367`、`include/strata/core/verify.hpp:357`），
双组时减半为 8。即**每层窗口最多 16 个 PCIe 直读 blob**。

读法：
- **单轮噪声很大**（同一臂内 38–52），所以只看平台区间的中位与上下沿：默认 48–52 明显在顶部，
  0.35 / 0.65 / 0.75 都落在 42–47；
- **ITL 更稳定**，排序同样是 0.55 ≈ 0.35 < 0.65 < 0.75；0.75 的 ITL 比默认高约 8%；
- 0.65 这一臂比 0.75 还差，说明 0.2 量级的差别已经在噪声地板附近——**结论只能是「没有一臂更好」，
  不能说「0.55 精确是峰值」**。

## 3. 机制：为什么两边都变差

打开 `STRATA_SPLIT_TIMING=1`（`src/program/generate.cpp:7411-7417`）读每窗口分项，
用相邻两次累计打印求边际（同一进程内，样本数 32 / 65）：

| `--pcie-frac` | 等 GPU（wait） | 池 + 规划（pool） |
|---|---|---|
| 0.55 | **24.5 ms** | **34.1 ms** |
| 0.35 | **12.3 ms** | **37.5 ms** |

把 PCIe 份额调小，GPU 侧确实少等了 12 ms，但 CPU 池多干了 3.4 ms 的活，**总时长反而更长**——
因为池本来就是更长的那条腿。反过来把份额调大，池缩短、GPU 等待变长，同样不赚。
**两条腿已经跨在交点上，没有白拿的余量。**

再看 `strata batch` 汇总行（同一负载的暖态）：

```
143 windows, avg 7.29 rows, 54.79 ms/window = run 51.60
  (CUDA0 GPU-reach wait 39.20 + CPU experts 40.67) + commit 3.16 + emit 0.03
per layer-window: CPU experts 8.86, VRAM hits 90.84, PCIe 8.94
```

- 每层窗口只有 **8.86 个**专家走 CPU 池，却花 **~34–41 ms**；
- 一个 IQ3_XXS 专家 blob 约 1.25 MiB，9 个 ≈ 11 MiB，34 ms 对应 **≈0.33 GB/s**；
- 这条腿的耗时几乎全是**每层每窗口的固定开销**（计划、激活量化、派发、门铃、同步），
  不是搬运字节数。

**推论**：`kStagingBlobs=16` 的 PCIe 上限在 S=4 下根本没被顶到——每窗口未命中约 18 个，
0.75 也只请求 ~13 个，小于 16。所以「把 kStagingBlobs 调大」在 S=4 上也不会有收益，
只有把 S 做大（每窗口未命中数上升）时才会变成约束。

## 4. 对 P4 目标的含义

P4 的原意是「减少 CPU 专家的活」。本次测量说明，在这个引擎的 S=4 稳态下：

- **不要动分流比例**（已经最优）；
- **不要做自适应控制器**（两个方向都更差，而且变化量在噪声地板）
- 真正的杠杆按收益排序：
  1. **减少窗口数**（每窗口出更多 token）——链式投机，但注意采样会关链（`temperature≠0` 整组退逐 token）；
  2. **减少每窗口的固定开销**——每层一次门铃 + 一次主机同步，这是 34 ms 的来源，
     对应「层优先 / 跨层全局调度」那条线（见 `~/docs/plans/` 与 memory `layer-major-scheduling`）；
  3. 提高命中率（P1 已证：放置策略换不来，只有显存预算能换）。
