# 如何复现「1M 上下文」测试

## 先理解：这里的"1M"怎么实现的

引擎原生窗口 = **262,144 token**。对外宣称的 1M 是**网关（RAG 组装）**提供的：

```
>262k 的输入 → 不拒绝、不截断：
   ① 最近 65,536 token 逐字保留（"最近窗口"）
   ② 其余内容切块（768 tok/块）→ 嵌入 → 按当前问题检索 + 重排 + MMR → 选出相关块
   ③ 组装成 ≤262k 的提示词送给模型
```

所以"支持 1M"= 输入被接受（不 400）且**答案正确**；正确性取决于"问题的答案能否被检索带回"。
判据日志（每次组装打一行）：

```
ctx[组装]: 窗口 262144 = 提示词 53405（原始 996471 tok） + max_tokens 1 + 边界 8 | 余量 208731 最近窗口 65544 + 检索块 26174
                                   ↑ 原始 = 用户发来的真实大小                                     ↑ 逐字保留      ↑ 检索带回
```

## 三种测法（从易到难）

### ① 标准 NIAH（针在草堆里）——应该全中

```bash
cd ~/bench
./venv/bin/python niah_run.py --url http://127.0.0.1:8080 --lengths 1000000 --depths 5,50,95
```

- 语料：Kamradt 原版 Paul Graham 散文（`/tmp/niah`，丢了就按脚本提示重下）；
- 针："The best thing to do in San Francisco is eat a sandwich and sit in Dolores Park..."，
  判定=回答里出现 `eat a sandwich`；
- **刚跑过的结果（2026-10-07 16:31，经网关）**：

  | 1M 输入 · 针深度 | 结果 | 组装后提示词 | TTFT |
  |---|---|---|---|
  | 5% | ✅ FOUND | 53,405 tok（原始 996,471） | 2.1s |
  | 50% | ✅ FOUND | 53,405 | 1.8s |
  | 95% | ✅ FOUND | 55,179 | 1.8s |

  深度 5%/50% 命中说明**检索把中段内容带回来了**（针不在最近窗口里）。

### ② 经真实出口（用户视角）

同一套脚本，换 URL 即可（客户端模型名 `qwen3.8-flash[1m]` 已验证可用）：

```bash
./venv/bin/python niah_run.py --url https://ssemarket.cn:23034 --lengths 1000000 --depths 5,50,95
```

或单发一条自建测试：

```bash
python3 ~/bench/channel_test.py needle --model strata-b --n 300000 --depth 0.5   # 超窗 → 组装
python3 ~/bench/channel_test.py needle --model strata-a --n 250000 --depth 0.5   # 原生窗口内
```

答案全文存档在 `~/bench/answers/`。

### ③ BABILong（散落事实）——已知困难档，**会失败，别当 bug**

```bash
./venv/bin/python babilong_run.py --url http://127.0.0.1:8080 --length 1000000 ...
```

1M 噪声文本里散落一条事实（qa2–qa5）：历史实测 **0/5** —— bge-m3 在"768 token 噪声块里夹一句话"
上区分度不足，检索带不回来。这是**检索的固有边界**，不是引擎窗口问题；要这个能力得上更强检索
或直接 1M 窗口的引擎。

## 判读速查

| 现象 | 含义 |
|---|---|
| HTTP 200 + 日志有 `ctx[组装]` | ✅ 1M 被接受并组装 |
| HTTP 400 `exceeds the context` | 网关计数出错（不该发生；把日志发我） |
| 日志有 `embed wait: N/N blocks in Xs` | 一次性灌入的正常预处理（等嵌入算完再检索） |
| 答案对但 TTFT 很久 | TTFT ≈ 嵌入等待（几百~千块约 5–60s）+ 读组装后的 5 万~21 万 token（单卡 ~3.4k tok/s） |
| 中段内容答不出 | 检索没带回（噪声文档的固有边界，见③） |

## 复测入口（汇总）
