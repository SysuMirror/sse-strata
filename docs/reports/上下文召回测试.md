# 1M token上下文召回测试集（下载链路+说明）

## 1. NIAH Needle-In-A-Haystack（优先测纯召回，1M可直接生成）
> 核心：动态生成任意长度（4k～2M+ token），在噪声文本埋事实，扫描埋藏深度，画召回热力图。
- 原版仓库（Greg Kamradt）：[https://github.com/gkamradt/needle-in-a-haystack](https://github.com/gkamradt/needle-in-a-haystack)
```bash
git clone [https://github.com/gkamradt/needle-in-a-haystack.git](https://github.com/gkamradt/needle-in-a-haystack.git)
cd needle-in-a-haystack
pip install -r requirements.txt
```
> 特点：**不需要下载预存数据集**，脚本自动拼接haystack文本，你可以直接配置 `context_length=1000000` 做1M token测试。
> 中文适配版本：国内OpenCompass NeedleBench，可直接接入OpenCompass评测框架。

## 2. BABILong【⭐最推荐测1M+，多事实分散召回】
> 支持生成**最高10M token**样本，不止单事实，多个事实分散在超长文本，测多实体追踪召回，专门针对百万token长上下文。
- Github：[https://github.com/booydar/babilong](https://github.com/booydar/babilong)
- HuggingFace数据集：[https://huggingface.co/datasets/RMT-team/babilong](https://huggingface.co/datasets/RMT-team/babilong)
```bash
# 直接huggingface datasets加载
pip install datasets
```
```python
from datasets import load_dataset
# 自带预生成 128k / 256k / 512k / 1M 样本
ds = load_dataset("RMT-team/babilong", "1m")
```
> 可选：也可以用仓库代码**自定义生成更大长度（>1M）**。

## 3. RULER（长上下文综合评测：召回+多跳推理，支持128k+，可扩到1M）
- 论文&代码：[https://github.com/hsiehjackson/RULER](https://github.com/hsiehjackson/RULER)
> 任务：单事实召回、多实体追踪、计数、聚合；合成可控任务，可配置超长上下文。
> 注意：原生默认到128k，修改代码即可生成1M长度。

## 4. LongBench v2（真实文本，8k～2M词，中文友好）
> 真实文档QA，不是合成噪声，适合验证**真实长文档理解**（不只纯召回）
- Github：[https://github.com/THUDM/LongBench](https://github.com/THUDM/LongBench)
- HF数据集：[https://huggingface.co/datasets/THUDM/LongBench-v2](https://huggingface.co/datasets/THUDM/LongBench-v2)
```bash
git clone [https://github.com/THUDM/LongBench](https://github.com/THUDM/LongBench)
```
> 注意：LongBench v2最长样本2M词，但**不是全部样本都是1M**，样本长度分布跨度大。

## 5. InfiniteBench ∞Bench（100k+，最长256k，不足1M，作为辅助）
> 上限256k，**达不到1M**，只能做辅助对比，不适合测1M窗口。
- Github：[https://github.com/OpenBMB/InfiniteBench](https://github.com/OpenBMB/InfiniteBench)
- HF：[https://huggingface.co/datasets/xinrongzhang2022/InfiniteBench](https://huggingface.co/datasets/xinrongzhang2022/InfiniteBench)

## 6. LongCodeBench LCB（1M上下文代码场景召回+代码理解）
> 面向代码仓库场景，1M长度真实代码库QA/debug任务，适合代码类LLM
- HF：[https://huggingface.co/datasets/Steefano/LCB](https://huggingface.co/datasets/Steefano/LCB)
- Github：[https://github.com/Zteefano/long-code-bench](https://github.com/Zteefano/long-code-bench)

# 推荐测试顺序（测1M上下文能力）
1. **BABILong 1M split**：先做多事实超长召回（硬指标，最严格）
2. **NIAH 1M自定义生成**：扫描不同埋藏深度，看位置衰减曲线（经典热力图）
3. LongBench v2：真实文档长QA，验证不是只在合成噪声上能过

1. **token计数一定要用模型原生tokenizer**，不要用gpt2/tiktoken估算，否则长度不准。
2. 显存压力巨大：1M上下文，FP16模型KV缓存会占用大量显存，需要确认你的推理引擎支持超长prefill（vLLM / FlashAttention / PagedAttention）。
3. NIAH/BABILong属于**合成探针**：过了只能证明「能从超长上下文召回埋藏文本」，不等于真实业务长文档推理没问题；必须搭配LongBench v2真实任务交叉验证。
